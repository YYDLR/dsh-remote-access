# 让手机在外面也能用家里电脑上的 DSH

> 把电脑上的 **DSH（DeepSeek Harness）** 发布到你的 **Tailscale** 私网，用手机浏览器随时随地使用；
> **用完之后自动释放会话写锁** —— 回到电脑前照常打开，两端不打架。

---

## ⚠️ 先读这一段：边界与风险

**这是一套民间方案，不是官方做法。** 在动手之前，请确认你接受下面这四件事：

| | |
|---|---|
| 🔴 **依赖未公开承诺的内部实现** | 整套方案建立在 DSH 的若干**内部行为**上：会话写锁是内核信号量、名字由路径 `sha256` 派生、锁**只在进程退出时释放**、会话目录的布局、`--trusted-host` 只校验 Host 头…… **这些都不是公开 API**，上游改掉它们时不会当成破坏性变更，**方案会静默失效**（不报错，只是不再工作） |
| 🔴 **只实测于一种环境** | Windows 10/11 + DSH 桌面版 `0.2.0-rc.2`。**只针对 DSH**，其他 AI 工具未验证 |
| 🔴 **凭据等价于那台电脑的控制权** | `dsh web` 的启动 token / 30 天 Cookie 会同时出现在日志和浏览器历史里。拿到它的人可以**在那台电脑上执行命令、读写文件** |
| 🟡 **锁的释放不是瞬间的** | 设计为**最长约 20 分钟**的自愈窗口（5 分钟会话文件静默 + 15 分钟无连接）。**做不到"用完即释放"**，因为 DSH 故意没提供超时释放 |

> **升级 DSH 之后，请重跑一遍指南第 7 节的验证。** 这是这套方案唯一的"体检"。

---

## 问题是什么

DSH 用一个**内核级的排他锁**保护会话写入。它的设计是：

> *"A live but wedged holder keeps the lock until its process exits: there is
> deliberately no expiry that could expropriate a stalled writer whose resumed
> appends would tear the log."*
> —— `dsh-session-persistence-jsonl/lib/index.js`

**翻译**：只要进程活着，锁就不放，而且**故意不做过期释放**。

于是形成一个死结：

```
关掉浏览器  ≠  dsh web 进程退出  ≠  锁释放
                                    ↑
                        只有"进程结束"才释放
```

你在手机上用过某个会话之后，回家打开电脑桌面版 → **"该会话已被占用"**。

## 怎么解决

**不是"用完退出"，而是"用完重启"。**

| 动作 | 效果 |
|---|---|
| 杀掉进程 | 锁被内核**立刻**回收 |
| 再启动新进程 | 新进程没打开任何会话 → **不占锁**，静静待命 |

```
手机浏览器
   ↓ https://<你的设备名>.<你的tailnet>.ts.net/    （仅 tailnet 内可达）
Tailscale 加密隧道
   ↓
电脑 tailscale serve（443）
   ↓
127.0.0.1:3081  ← dsh web（只绑回环，尊重 DSH 的安全设计）
   ↑
guard 守护脚本 —— 自启 / 保活 / 空闲后重启以释放锁
```

守护脚本（`dsh-web-guard.ps1`）负责：

1. **自启**：计划任务在登录时拉起
2. **保活**：keepalive 每 5 分钟敲一次门
3. **释放**：无连接 **且** 会话文件静默 5 分钟，持续 15 分钟 → 杀掉 dsh web 并重启（**锁随之释放**）
4. **待命**：没追踪到任何会话文件时**不计空闲、永不重启** —— 此时那个进程不可能持有锁

## 快速开始

**完整步骤见 [`docs/GUIDE.md`](docs/GUIDE.md)**（约 30 分钟）。

大致是：

```
1. 装 Tailscale（电脑 + 手机，同账号）
2. （可选）开 SSH，让手机上的 AI 能代你操作电脑
3. 写 dsh-web-start.bat         ← 启动 dsh web
4. 写 dsh-web-guard.ps1         ← 守护脚本（核心）
5. 建两个计划任务               ← onlogon 自启 + 每 5 分钟保活
6. tailscale serve --bg 3081    ← 发布到 tailnet
7. 验证（含"用手机蜂窝流量打开一次"这一步）
```

## 实测数据

这套方案在作者机器上跑过完整验证：

| 层面 | 结果 |
|---|---|
| **链路通** | Tailscale → serve → `127.0.0.1:3081`，正常响应 |
| **锁能释放** | 手机停止使用后 **19 分 32 秒**自动释放（上限 20 分钟） |
| **锁状态可验证** | 锁探针（`scripts/dsh-lock-probe.ps1`）**双向对照**：持有 → `LOCK IS HELD`；空闲 → `LOCK IS FREE` |
| **真正在门外可用** | 关掉手机 Wi-Fi、**改用蜂窝流量**，正常访问 |
| **待命不折腾** | 无人使用时**连续 3 小时零重启**（v4 时代会每 15 分钟自杀一次） |

> 关于"锁探针"：它读取 DSH 用的那个**具名内核信号量**的状态。
> 注意它**必须正反各跑一次**才算数 —— 只看到一次 `NOT FOUND` 什么也证明不了
> （名字算错也会稳定输出 `NOT FOUND`）。详见指南 `7⑤`。

## 已知限制

- 电脑**睡眠**后远程会断 —— 指南 `1.4 检查项 1` 给了处理办法
- 重启后若**无人登录**，`onlogon` 任务不触发 —— 指南 `1.4 检查项 3`
- 守护脚本**可能追踪到"别人的"会话文件**（需要三个条件同时满足才触发，指南第 9 节）
- 失败退避逻辑**未在真实故障下实测**
- **手机端用不了「仅限本机」的管理功能** —— 提供商目录、凭据、部分设置会被拒（`isLoopback=false`）。
  这是 DSH 的**刻意设计**，也是本方案的**有意取舍**：配置类操作请回到电脑本机做。
- **本方案定位是「个人自用」**（一个 tailnet 里只有你自己的设备）。要分享给别人，先把 Tailscale ACL 和 SSH 权限收紧。
- 装了火绒 / 360 等安全软件时，它们可能把守护脚本的行为当成可疑活动 —— 指南第 6 节有说明
